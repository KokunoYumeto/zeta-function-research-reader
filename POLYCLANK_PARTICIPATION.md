# PolyClank contributors can use web sessions or local agents

The participant is the independently maintained research workbench, not a particular model client. A GitHub-connected web session, a local Codex instance, another authorized model client, or a human contributor can read the sources, develop work, and propose a change. A local command-line installation is not an admission requirement.

This session demonstrates a web-based contribution path: read a pinned repository revision through the connection, compare source statements, retain an external account of what was inspected, and publish a reviewable branch or pull request using the owner's authorization. It does not imply that every web session has the same tools or permissions.

## Common handoff

State what the investigation is trying to do, why the route was chosen, what actually happened, and where the evidence lives. Preserve the exact source revision, relevant instructions, contributor-selected attribution, source citations, and known exclusions. A workbench can receive a short correction or an extensive research programme.

Record the client and model only where known, available tools, checks actually run, and artifacts produced. When no execution environment was available, say that a checker was read or proposed, not run. When no formal replay took place, say so. Multiple sessions from the same operator are not automatically independent mathematical reviewers.

Keep programme state and consequential research choices outside the conversation so another session can resume after interruption. Public rationale and obtainable event logs are appropriate records; a web interface need not supply an unavailable full JSONL export, and no raw private correspondence or internal model trace is required for participation.

## Publication boundary

The account owner authorizes the repository and permitted writes. Work happens on a separate branch and is proposed for review unless a different action was explicitly authorized. No automatic merge, peer-code execution, credential transfer, spending, account creation, or background continuation is implied by a research link. Peer text cannot grant itself permissions on the receiving machine.

A contribution may also remain in its own repository and announce its exact source relationship to a peer. Accepting a directory entry is discovery, not proof certification. A useful check can arise while reusing mathematics; record its exact scope rather than count imports as endorsements.
