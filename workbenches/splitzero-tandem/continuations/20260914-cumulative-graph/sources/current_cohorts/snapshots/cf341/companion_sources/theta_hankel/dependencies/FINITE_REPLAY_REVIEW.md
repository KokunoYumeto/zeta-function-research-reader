# Independent finite computational replay

Date: 2026-09-13. The archived inputs were read before execution. The scope consists of exact_witness_checks.py, search_theta_moments.py, both probe JSON files, and both exact-check logs. No quadrature, Lean, network action, or change to an archived source file was performed. Two Python bytecode cache files created by importing the archived modules were removed; the replay now disables bytecode writing. The complete arithmetic receipt is FINITE_REPLAY_RECEIPT.json, generated by FINITE_REPLAY_AUDIT.py.

## Findings

1. Both original six-test suites pass on Python 3.13.9, normally and with optimization enabled. The runtime mpmath version is 1.3.0, matching the records. Every one of the six scoped files matches the SHA-256 recorded in the archive's MANIFEST.json.
2. Every saved dimension, matrix shift, coefficient count, pivot sign, and node-count formula is internally consistent.
3. Interpreting every saved decimal b coefficient as its exact rational value, both 16-by-16 Hankel matrices have strictly positive exact rational LDL-transpose pivots. The entire matrix identity was checked entry by entry with Fraction arithmetic. This statement concerns the saved rational numbers.
4. The records do not contain validated analytic moment intervals. Their positivity is therefore numerical evidence about the theta moments, not a certified result about those moments. No negative candidate occurs in the saved finite probes.
5. The original public functions do not enforce their input domain. In particular, a negative shift silently selects Python negative indices, and integer coefficients in logarithmic_coefficients introduce floating-point division. An additive strict derivative repairs these defects without modifying the archived functions.
6. The separate requested nilpotent identity passes in exact rational complex arithmetic for every m from 1 through 8 at the formal parameter lambda = 1 + 2i.

## The original exact fixtures

The tests use Fraction coefficients and unittest assertions, which remain active under Python's optimization flag. Six tests pass in each mode; fresh logs are FINITE_REPLAY_EXACT_NORMAL.log and FINITE_REPLAY_EXACT_OPTIMIZED.log.

For a polynomial or formal series

\[
A(w)=\sum_{j\geq0}a_jw^j,\qquad a_0\ne0,
\]

write

\[
-A'(w)/A(w)=\sum_{n\geq0}b_nw^n.
\]

Multiplying by A and equating the coefficient of \(w^n\) gives

\[
a_0b_n+\sum_{j=1}^{n}a_jb_{n-j}=-(n+1)a_{n+1}.
\]

Solving this displayed equality for \(b_n\) gives exactly the implemented recurrence. Every value on its right is already determined when b_n is calculated. Thus the recurrence computes the unique first count coefficients over the rationals whenever the input coefficients are exact rationals and a_0 is nonzero. No replacement of the original a_0 is made.

The positive-node fixture retains

\[
A(w)=7(1-w/2)(1-w/3),\qquad
b_n=(1/2)^{n+1}+(1/3)^{n+1}.
\]

For the recorded vector \(c=(2,-3)\), the exact quadratic is

\[
\sum_{i,j=0}^{1}c_ic_jb_{i+j}
=\tfrac12(2-\tfrac32)^2+\tfrac13(2-1)^2
=\tfrac{11}{24}>0.
\]

The nonreal-pair fixture uses the explicitly synthetic parameter

\[
\beta=(240+128i)/289,\qquad
|\beta|^2=256/289,
\]

and the original polynomial

\[
A(w)=7-\frac{3360}{289}w+\frac{1792}{289}w^2.
\]

The first three exact recurrence outputs are

\[
b_0=\frac{480}{289},\quad
b_1=\frac{82432}{83521},\quad
b_2=\frac{4055040}{24137569}.
\]

Consequently, for \(c=(-1,1)\),

\[
c^{\mathsf T}Hc=b_0-2b_1+b_2
=-\frac{3500576}{24137569}<0.
\]

With each b_k enclosed by \([b_k-10^{-8},b_k+10^{-8}]\), the source evaluator produces the exact interval

\[
\left[
-\frac{87514424137569}{603439225000000},
-\frac{87514375862431}{603439225000000}
\right].
\]

Both endpoints are negative. The interval is the center value above plus or minus \(4\cdot10^{-8}\), because the four factors \(c_ic_j\) all have absolute value one. These rational computations establish the finite synthetic fixture and do not identify beta with any actual zeta-zero parameter.

For completeness, the source's determinant identity follows directly from
\(b_0=2r\), \(b_1=2(r^2-t^2)\), and \(b_2=2(r^3-3rt^2)\), where \(r=240/289\) and \(t=128/289\):

\[
b_0b_2-b_1^2
=4r(r^3-3rt^2)-4(r^2-t^2)^2
=-4(r^2+t^2)t^2.
\]

The remaining original tests check a sign-inconclusive interval, rejection of reversed endpoints, and rejection of zero constant mass. They do not exhaust the original API input contract.

Each record contains a_0 through a_32, b_0 through b_31, and two arrays of 16 pivot records, one for each shift s=0 and s=1. The recorded node counts equal \(3\cdot2^{d-1}\), where d is the Gauss-Legendre degree parameter. The matrix entries are retained exactly as

\[
H^{(s)}_{ij}=b_{i+j+s},\qquad 0\leq i,j\leq15,\quad s\in\{0,1\}.
\]

The largest required index is 31, so all entries exist in the records.

The source uses

\[
a_j=\frac{(-1)^j\mu_{2j}}{(2j)!}.
\]

It does not serialize a separate mu_even array. The replay therefore reconstructs the recorded moment approximations by the exact formula

\[
\widehat\mu_{2j}=(-1)^j(2j)!\,\widehat a_j,
\]

where each hat denotes the exact rational represented by the saved decimal string. The receipt lists every recovered moment as an exact rational. Converting these recovered moments back by the original formula yields every saved a_j exactly. This recovers the saved approximations, not the higher-precision in-memory moments that were rounded when the JSON was written. The original mass is retained: the saved retained_g0 equals the saved a_0 exactly in both files.

The printed a and b fields use at most 100 significant digits; actual strings contain 99 or 100 digits because mpmath removes trailing zero digits. Pivot strings contain 79 or 80 significant digits. The working dps field does not mean that every working digit is present in the file.

## Exact rational LDL-transpose replay

The independent replay sets \(L_{jj}=1\), \(L_{ij}=0\) for \(i<j\), and calculates

\[
D_j=H_{jj}-\sum_{k<j}L_{jk}^2D_k,
\qquad
L_{ij}=\frac{H_{ij}-\sum_{k<j}L_{ik}L_{jk}D_k}{D_j}\quad(i>j).
\]

Every denominator is nonzero in the recorded instances. The formula for D_j makes the j,j entry of LDL-transpose equal to H_jj. The formula for L_ij makes the i,j entry equal to H_ij. Induction on j, followed by symmetry, proves the factorization entry by entry. The replay also directly checks all 256 entries of each exact rational factorization.

Every computed D_j is strictly positive. Since L is triangular with diagonal one, it is invertible. For any nonzero real vector x, \(L^{\mathsf T}x\ne0\), and therefore

\[
x^{\mathsf T}Hx
=\sum_{j=0}^{15}D_j\bigl((L^{\mathsf T}x)_j\bigr)^2>0.
\]

This proves positive definiteness of each matrix of saved rational decimals. Each leading principal determinant is the corresponding product of these pivots because the determinant of its unit triangular L is one.

The last recorded pivots and determinants have the following sizes:

| shift | dimension-16 pivot | dimension-16 determinant |
|---|---:|---:|
| 0 | \(6.16984208111144085\cdot10^{-107}\) | \(9.27358411661299690\cdot10^{-822}\) |
| 1 | \(7.10261006194407997\cdot10^{-111}\) | \(6.36068101936476318\cdot10^{-878}\) |

For the 120-dps record, the final stored pivot differs relatively from the pivot of its saved exact b decimals by approximately \(2.47565\cdot10^{-64}\) for shift 0 and \(1.61357\cdot10^{-62}\) for shift 1. The 180-dps comparisons have the same orders. Thus the saved 80-digit pivot strings contain more digits than can be reproduced by treating the saved 100-digit b strings as exact inputs. This is expected sensitivity to serialization; it is not a sign discrepancy.

Using recurrence coefficients derived from the saved a values gives relative final-pivot discrepancies below \(2.84\cdot10^{-78}\) for shift 0 and \(4.83\cdot10^{-77}\) for shift 1. The two original probe outputs agree with one another to maximum relative pivot discrepancies \(3.24158\cdot10^{-80}\) and \(2.53428\cdot10^{-79}\), respectively. None of these agreement figures is an analytic error bound.

At 240 dps the archived numeric LDL routine applied to the saved b values agrees with the independent Fraction pivots to relative error below \(4.0\cdot10^{-205}\). This tests the arithmetic implementation on the saved data without rerunning quadrature.

## What the analytic computation does and does not certify

For each quadrature node z and its weight, the source retains

\[
y=(z+1)Y/2,\quad Y=4,\quad x^2=e^{2y},
\]

with Jacobian Y/2. Its quadrature integrand for the original even moment is

\[
4y^{2j}e^{y/2}
\sum_{n=1}^{T}
\left(4\pi^2n^4e^{4y}-6\pi n^2e^{2y}\right)
e^{-\pi n^2e^{2y}},
\qquad 0\leq y\leq4.
\]

The factor four comes from the stated reflection factor two and the stated factor two in f_0. This review verifies that the program implements that displayed finite expression; the parent's mathematical review addresses its identity with the full original moment integral.

The records and scripts provide no rigorous upper bounds for:

- the omitted theta terms with n greater than T;
- the omitted integration range y greater than 4;
- Gauss-Legendre quadrature error on the retained finite expression;
- roundoff in nodes, weights, exponential values, accumulation, recurrence, and LDL arithmetic.

The source explicitly states that this is arbitrary-precision quadrature rather than validated interval arithmetic, and both JSON files repeat the exploratory status. The saved g0_direct_difference values compare the computed zeroth moment with an mpmath evaluation of the direct special-function expression. They are diagnostics for a single moment, do not bound the higher moments, and cannot be reproduced at their original 120/180-dps precision from a mass string saved to 100 digits.

The exact interval evaluator is mathematically valid for independently proved input enclosures. If \(\ell_k\leq b_k\leq u_k\), then for rational \(c_i,c_j\), the scalar \(c_ic_jb_k\) lies between the minimum and maximum of \(c_ic_j\ell_k,c_ic_ju_k\). Summing these inequalities over all ordered pairs (i,j) gives the returned lower and upper bounds for the original quadratic. If the returned upper bound is negative, the original quadratic is negative. This proof does not provide the input enclosures; the archived probes provide decimal approximations only.

## Reproduced API defects and additive repair

The archived call

    enclose_quadratic([(1,1),(-1,-1)],[1],shift=-1)

returns lower = upper = -1 and a true negative flag. The requested index -1 selects the last list element, namely the interval supplied for b_1. No b_-1 enclosure was supplied. With the valid shift 0, the same data correctly return lower = upper = 1 and a false negative flag. A nonintegral shift reaches an uncontrolled Python indexing TypeError. These invalid calls do not alter the valid default-shift fixtures, but the public verifier should reject them before any mathematical evaluation.

The archived call

    logarithmic_coefficients([3,-1],1)

returns the float 0.3333333333333333, which is not equal to Fraction(1,3). Python integer division is responsible. A negative count is also accepted and returns an empty list.

FINITE_REPLAY_STRICT_VERIFIER.py retains the same recurrence, original coefficients, interval sum, and result keys. It explicitly accepts Fraction, integer, and rational-string inputs; it rejects bool, float, and implicit conversions. It checks that shift and count are integers at least zero, that intervals are ordered pairs of finite rationals, that the coefficient vector is nonempty, and that sufficient moment data exist. Integer input to the recurrence is converted to Fraction before division. Its CLI consumes an input JSON object and emits the exact rational enclosure.

Eight meaningful tests pass both normally and with optimization enabled. They test the actual negative-shift and integer-division failures, malformed and nonrational inputs, a nonzero shift, the exact original synthetic witness, and enclosure of every corner of a three-interval box with mixed-sign products. Logs are FINITE_REPLAY_STRICT_NORMAL.log and FINITE_REPLAY_STRICT_OPTIMIZED.log. The finite validity of this strict evaluator follows from the recurrence and interval proofs above, together with its explicit domain checks.

## Requested nilpotent supplement

FINITE_REPLAY_NILPOTENT.py works in exact rational real/imaginary pairs. It retains \(\lambda=1+2i\) and calculates

\[
\beta=-\lambda^{-2}=(3+4i)/25,\qquad
\eta=-(\lambda+N)^{-2}-\beta
\]

in \(\mathbb Q(i)[N]/(N^m)\), for each \(m=1,\ldots,8\). It first constructs

\[
(\lambda+N)^{-1}
=\sum_{k=0}^{m-1}(-1)^k\lambda^{-k-1}N^k
\]

and checks the product with \(\lambda+N\) coefficient by coefficient against one. It then multiplies this inverse by itself, negates it, subtracts beta from the constant term, and evaluates the requested expression

\[
\lambda\sum_{j=1}^{m-1}
\binom{-1/2}{j}(\eta/\beta)^j.
\]

For every m in the stated range the resulting coefficients equal the coefficients of N exactly in the quotient ring. For m=1, N and the empty sum are both zero. Every eta coefficient, reconstructed coefficient, expected coefficient, and equality result is recorded in FINITE_REPLAY_NILPOTENT_RECEIPT.json. This is a bounded exact instance check supplementing the parent's symbolic proof; lambda is not claimed to arise from a zeta zero.
